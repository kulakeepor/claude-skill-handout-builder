# 内容协议

## 源覆盖台账

工作目录放持久磁盘，如 `~/handout_work/<任务名>/`。记录源 SHA-256，避免素材文件列表变化导致编号漂移。页码统一为 PDF 物理页码，从 1 开始，注明与印刷页码的区别。

每个内容单元至少记录：

| 字段 | 含义 |
|---|---|
| id | 稳定 ID，不依赖本次 glob 排序 |
| source | 文件哈希、页码、坐标矩形列表，可跨页 |
| kind/order | 标题、正文、题目、选项、表格、公式或插图及阅读顺序 |
| source_evidence | 原始文本、高清裁图文件、OCR 候选和实际工具来源 |
| content | 按阅读顺序保存文字/run/表格单元格/图片引用 |
| critical_tokens | 原文中的数字、单位、符号、上下标等与逐项核对结果 |
| figures | 源矩形、图注、所属题目、裁图路径、文件哈希和显示尺寸 |
| decision | 冲突与裁决依据；图像回退及原因 |
| output_locator | 输出段落/表格/图片实例位置 |
| status | pending、verified、image_preserved 或 unresolved |

覆盖以入选集合为边界：每个入选内容区域都有输出；每个输出摘录都有源证据，重述、改编或新编按 provenance.md 记录。未入选源页只记录查看范围，不宣称全篇覆盖。页眉页脚、页码、水印可作为非教学元素排除并记账；组编学生版可以排除源答案；重复内容按 selection.md 取舍并记账。用户指定的必用内容不能自动排除。多栏阅读顺序和跨页续题必须人工判断并留证据。

## 核对方法

- 有文本层：按 bbox 获取原文，与页面区域逐块对照。文本层可能有错误、遗漏或错误排序，也需要视觉核对。没有缺字符标记不等于没有漏下标。
- 扫描/路径字形：区域 300–600dpi 渲染，疑难单字提高到实际可辨认的分辨率。OCR 候选应在看到预期题干/答案前产生，避免暗示。两次同模型同输入或两个 OCR 共用同一识别结果，不视为独立依据。
- 数字核对包括小数点、负号、范围、百分号、科学记数法和单位大小写。符号核对包括 R₀/R₁、U/I、≤/≥、×/x。上标/下标与基字的绑定必须保留。
- 分数、根式、方程组、表格必须核对结构，不能仅比较文本串。不得把 U²/R 改成 U2/R；简化为线性表达式也须语义等价且与用户排版需求相容。
- 物理推导能发现可疑数据，不能更正原 PDF。源疑似笔误按原文保留，在交付说明中单独注明。

## 图片

PDF 内的“图片数量”不是题目配图数量：电路可能是路径，标签可能是文字，整页也可能只是一张扫描图。按视觉内容划分区域。

优先从原页渲染图裁剪完整视觉区域，含刻度、单位、图例、甲乙丙和 A–D 标签，不重画电路。嵌入位图 bbox 只是定位线索，不能证明完整图界。先看含邻域的原裁图，再仅收白边；图与题目归属依据标签、位置及上下文核对。

记录裁图像素尺寸、非白像素比例和显示尺寸对应的有效 DPI；这些只能拦截空白和分辨率问题，不能证明裁对图。必须同时核对原图和输出图；不得凭“看上去像电路”认定正确。每个输出图实例都对账，同一图片被多处复用时不按媒体文件个数验收。

无法识别但清晰可复制的表达式可以原图保真；原 PDF 本身模糊且放大无助时标记 unresolved，不用截图掩盖不可读问题。回退不能吞掉邻近正文，也不能裁掉公式的上下标或括号。
