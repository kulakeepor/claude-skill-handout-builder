# 验收与交付

这是一份执行协议，不是现成自动验收引擎。执行者需针对本次台账生成程序化对账，并结合原 PDF 逐块视觉核对；不得把“按协议操作”写成测试已通过。

## 五个独立关卡

| 关卡 | 通过证据 | 不能替代它的检查 |
|---|---|---|
| 源覆盖 | 入选集合全部记账；续题、多栏、正文、选项、图注均有归属 | 题目标记数、页数或字数 |
| 源忠实 | 摘录单元与原页对照；改编按记录核对差异并验证解答；关键 token 和结构逐项裁决，unresolved=0 | OCR 一致、答案合理、模型自报高置信 |
| 输出一致 | 保存后重开 docx，按台账读取正文/run 上下标/OMML/表格/图片实例并对账 | 生成前 transcripts 检查 |
| 版式 | 最新文件渲染全部页，无缺字、遮挡、截断、模糊、图注脱离或表格越界 | 只抽首中末、页数变化阈值 |
| 真实粘贴 | 目标应用全篇复制→空白/已有内容目标文档，保存后回读与全页渲染 | XML 合并、anchor=0、只打开原 docx |

输出检查：浮动 anchor、文本框、VML、OLE、外链图片、正文分节符、定位大缩进为零；ZIP 完整、关系目标存在。统计缺陷实例并列位置。结构零风险仍不证明实际粘贴稳定。

对账只允许已列出的版面差异，如视觉换行和页面号码。比较时不得一律删除空白、符号或上下标来“让 diff 通过”；数学空格与负号等可能有意义。组编允许重编号，记录映射并检查引用与答案对应。

图片对账包含源区域→裁图→DOCX 媒体→正文引用关系。媒体哈希证明文件未被替换，不能证明裁图范围正确。字数一致、图数一致均只是弱信号。

## 验收报告最小内容

保留 `acceptance.md` 或等价结构化报告，记录源/输出哈希、模板、覆盖范围、单元数、图片实例数、关键项核对数、图像回退位置、每关 pass/fail/not_run、实际执行工具、证据路径、未解决项。修改最终文件后更新哈希，重验受影响关卡；报告不能沿用旧输出。

没有实际原 PDF 的技能重建任务，只能验证技能结构与现有工具，不能宣称完成真实文档验收。没有目标应用访问时可完成源忠实与静态结构检查，但应报告真实粘贴未验证，不能要求用户代做作为质量承诺的依据。

## 回归样例

投入常规使用前选择真实素材，至少覆盖：可提取文本但下标路径化、整页扫描、左右双栏、左文右图、跨页续题、含甲乙丙的多图、A–D 电路选项、表格、复杂分式以及 WPS 候选数字与原图冲突。样例应有原图可直接确定的参考值，不能用被测试的 OCR 创建参考答案。

检查能力要用故障验证：故意错一个小数点/上下标、删除选项、交换题目图片、裁掉图注、插入 anchor、粘贴到同名但不同格式的样式文档。应分别由对应关卡发现；未执行这些试验不能声称自动拦截能力已得到证明。

## 交付措辞

全部完成：说明已核对多少内容单元、原图实例与关键项，在哪个应用测试了何种粘贴；列回退数量。图像回退存在时不得称“全篇公式均可编辑”。

检查未完成：明确具体检查与原因，提供可用候选稿和已有证据；不说“可放心复制”“零丢失”或“全部通过”。对模糊源中无法辨认的内容说明具体位置，不能把核对任务笼统推回用户。
